# v1.18.6 — Paid Service Trial Claim recovery and provider metadata

This patch fixes public Issue #21. It preserves the published v1.18.5 artifacts.

`PaidServiceTrialTaskClient(claim_directory=...)` saves each original Claim
request before sending. `recover_claim(task_id, idempotency_key=...)` uses that
same request/key after an unknown outcome or restart, or returns a durable saved
credential. The client returns no Claim until credential/journal persistence
succeeds. Keep the same directory for the purchase executor; never delete its
history to retry. Explicit v1 and default v2 keep their original identities and
deadlines. There is no automatic new Claim or unbounded retry loop.

Bounded, unrelated Bazaar/discovery extensions are ignored after recognized
payment conditions are validated. Contradictory economics, domains, aliases,
timeouts and unsupported authorization methods still stop before purchase.
Seller address spelling and the fixed GET/POST request remain unchanged.

See the [native Python quickstart](../01_quickstart.md#paid-service-trial-native-python).
No API/Task Definition/pack change, live purchase, paid CLI/MCP capability or
new generic payment behavior is introduced.
