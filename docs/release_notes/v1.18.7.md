# v1.18.7 — Standard Paid HTTP and safe Claim diagnostics

Paid Service Trial now retains Payment-Required and Payment-Response through its
standard HTTP parser. Valid header-led 402 responses work with ordinary JSON,
HTML or empty bodies. Header multiplicity, HTTP limits and request identity stay
intact. A returned transaction locator is still not payment or reward confirmation.

PaidServiceTrialError keeps received status_code and validated public_error_code,
reason and optional request_id, including CLAIM_OUTCOME_UNKNOWN. Existing exception
names and catches remain supported. Request IDs outside 1–256 visible ASCII
characters are omitted without changing the API result. Cached rejections retain
safe details, and existing 1.18.6 records remain readable.

For Claim recovery, preserve the original Task ID, key, client version and private
directory before sending. recover_claim reads that saved request even when the
first call returned no Execution ID, credential or token. It does not create a new
key or extend the original deadline. See the [native Python quickstart](../01_quickstart.md#paid-service-trial-native-python).

Standard Paid LN API reads now use the remaining finite request budget rather
than a separate 10-second read cap. The overall 20-second budget, DNS/connect/TLS
bounds and zero automatic retries stay unchanged. This covers valid delayed
responses within the existing budget; delivery loss and expiry can still leave
Claim outcome unknown. It does not establish the cause of a particular live
incident. `recover_claim` already exists in 1.18.6; 1.18.7 is not its introduction.

API/Task Definition versions, both formal packs, seller address spelling,
extensions validation and purchase/report replay limits are unchanged. No new
recovery API, overall timeout increase or paid CLI/MCP capability is introduced.
