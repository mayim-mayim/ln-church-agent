# 1.18.8 — Agent API access quota (publication candidate)

This candidate adds explicit access-quota purchase and recovery for the LN Church
Agent API on **Base mainnet (`eip155:8453`)**, using native USDC. Publication remains a separate Release step. On 2026-09-26 Development Control
received via the Human the reported passing OpenClaw live mainnet E2E for the c3
SDK source. That report is distinct from source acceptance and from the rebuilt
c4 documentation artifacts, which have not been live-payment retested.

## Access purchases

All four Task families share one access policy: v1.17 Task Venue, Scheduled HTTP
GET Batch, Immediate HTTP Visit, and Paid Service Trial. Automatic access spending
is disabled by default. Opt in with a separate explicit access budget and signer;
a Task purchase budget or wallet balance does not authorize access spending.
The current access purchase price is 0.01 USDC (10,000 atomic units). The server
provides the free-window reset and purchased-request allowance in its challenge.

A pending purchase reserves budget and retains its original request, challenge,
payment proof and Claim key. Confirmed payment is counted once. Only a confirmed
FAILED_FINAL purchase releases its reservation. Purchased credits have no expiry;
GET result expiry does not undo payment or credits. Edge owns admission and
remaining credits; SDK snapshots are observations, not an authoritative balance.

## Explicit continuation

- Re-enter the same operation with the same live policy to continue a pending
  purchase using the same proof. No new nonce is generated for that recovery.
- After a PAID public GET returns result_expired or result_unavailable, that call
  reports the terminal error. A later explicit GET is an ordinary admitted use,
  without reusing the old purchase proof for free current results.
- After a confirmed failed access purchase, explicitly call
  `finish_failed(purchase_id)` before selecting a new purchase for the same Paid
  Claim request. The original Task, body and Idempotency-Key remain fixed.
- Sent/unknown Claims and readonly misses do not become new Claims. Existing
  transport bounds, DNS pinning, redaction and once-only payment rules remain.

### Documentation clarification (c4)

The [finite GET example](../access-quota.md#pending-get-keep-the-session-and-explicitly-continue)
keeps the same process, client, `AccessQuotaPolicy` and arguments from the first
`AgentTaskClient.list_tasks(limit=1)` through optional status checking and explicit
normal continuation **outside `read_only`**. A repeated pending response returns
control with that live state; it does not trigger polling or a replacement policy.
`read_only` retrieves purchase status/saved results without starting an unexecuted
GET. A saved result completes recovery; no further ordinary GET is then needed.

A success receipt/Tx or recorded spend can coexist with a pending original
result: **payment confirmed; original request result unconfirmed**. Receipt alone
does not prove the GET unexecuted. Continue the existing operation without
repurchase or a new signature. Snapshot receipt/quota fields describe the
purchase/response time and cannot guarantee current remaining credits.
`spent_atomic` / `reserved_atomic` are USDC atomic-unit accounting for the retained
policy, not remaining API accesses. These GET instructions do not authorize new
resubmission of sent/unknown Claims.

For signing expiry, the server boundary is
`current_time < validBefore <= expires_at`; the SDK generates
`validBefore = expires_at`. Equality is not a mandatory server restriction;
challenge, network, token, recipient, nonce and other validation still apply.

See [access quota usage](../access-quota.md) for configuration and caller examples.

## Scope and limitations

Access purchase state is memory-only. This release does not add serialization or
restoration of that state across process restarts. Creating a new policy after a
restart does not recover the old purchase. Do not treat a lost policy as
an unused budget or as permission to repurchase an unresolved operation.

The accepted product target is Base mainnet. The existing explicit Base Sepolia
lane is not qualified for this release: its token signing domain differs from
the server's testnet domain. This metadata candidate does not change that lane.

Task success schemas, contract packs, dependencies, Python support declarations,
and package implementation are unchanged from the accepted access-quota c2.
MCP remains keyless and inspect-only with no wallet, signing or payment tools.
Version metadata is 1.18.8; private evidence, internal skills and release operator
materials are excluded from wheel/sdist. Earlier public release history is kept.
