# 1.18.5 — Paid Service Trial SDK

Adds the explicit native Python `paid_service_trial.v1` client, strict DTOs,
single-purchase executor, private durable journal and existing-purchase import
descriptor. The release identity is 1.18.5 across package, runtime User-Agent and
MCP metadata. Publication is a separate release operation.

A worker obtains a successful Claim and buys with its reward wallet after fixed
requirements, PaymentPolicy and a bounded sealed Base block guard pass. It saves
the nonsecret identity before one paid dispatch, reports promptly even without a
Tx hash or successful HTTP response, and recovers by reading the same Submission
before any report replay. Report receipt, independent verification, approval and
confirmed reward payment are separately modeled.

Recovery reads the server's saved result even after the verification deadline.
Eligible witness acceptance before that deadline can lead to later approval;
an earlier terminal no-reward result stays final. An elapsed deadline or unknown
write outcome alone does not establish nonpayment, rejection or approval.
When `verified_at` represents witness acceptance, it is the server's recorded
verification time, distinct from storage acknowledgement, reward approval and
payout confirmation. The SDK never supplies that timestamp or buys again during
recovery. The preserved v1 semantic fixture is 1.0.1; its Task Definition remains 1.0.0.

The new immutable resources mirror the Backend-owned pack byte for byte. Existing
three Task families, their unqualified discovery, generic payment behavior,
registration timing, package dependencies, platform support and CLI/MCP entry
points remain unchanged. Native Python execution does not add a new smart-wallet
signer, a paid Offer-registration wrapper or a payout SLA. Requester import can
describe existing supported mined purchases without local EOA signature checks.

The [Agent Guide (SKILL.md)](https://kari.mayim-mayim.com/agent-task-specs/paid_service_trial.v1/1.0.0/SKILL.md)
and [Requester Guide](https://kari.mayim-mayim.com/agent-task-specs/paid_service_trial.v1/1.0.0/requester-guide.md)
describe the new profile. Runtime availability requires the corresponding backend
release and its exact contract bundle.

## HTTP v2

Normal new clients select `paid_service_trial.v2` / Definition `2.0.0`.
Explicit `version="v1"` creation and saved v1 recovery keep their original
schemas, digests, journal paths and six resource files. The v2 mirror has its own
six Backend-owned files; a missing pack fails closed before paid execution.

V2 freezes method, URL/query, public canonical JSON text, body hash and
request/purchase/Offer digests. GET stays bodyless; POST sends those exact bytes.
Unpaid terms checks send the same request and can cause target-side effects.
Strict JSON/JCS handles finite binary64, safe integers, Unicode preservation,
UTF-16 ordering, duplicate keys, depth and byte bounds. No generic serializer,
RPC guard, dependency, platform or release-version behavior changes.

The v2 journal retains original R and full nonsecret authorization across
restart, report/status recovery and transaction supplementation. Conditions
observed to change before dispatch stop that request. Ambiguous dispatch cannot
create another paid send, nonce or automatic purchase. Existing-purchase export
adds explicit R, selected terms and their digests without I/O; preserve its UUID
and omitted optional identity fields on retries. Public request body is input;
private credentials, signatures, seller response body and Sample/fee evidence
remain excluded. Payment verification does not prove historical HTTP execution.
External Sample cost and LN fee remain separate. Publication requires its own
release authority.
