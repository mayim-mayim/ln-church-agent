# Release v1.18.2 — Source Simplification

Version 1.18.2 simplifies the existing SDK implementation and its test scaffolding. It preserves the public SDK interfaces, existing Task wire profiles, local payment authority, and the journal and recovery boundaries described in the SDK documentation.

## Changes

- Consolidates internal payment flow, challenge parsing, redaction, model validation, and private-file handling; removes obsolete historical-candidate assertions and duplicated compatibility scaffolding.
- Exposes received purchase-result metadata through the existing private metadata interface. The Monzen and Bazaar Surface Comparison Facts purchases, Domain Observation Slot, and Verified Domain Track retain result handles, request hashes, and result expiries without inferring them from the business body or the product expiry.
- Keeps result recovery and goal-summary reads non-purchasing. Unexpected HTTP 402 responses do not trigger payment or automatic purchase navigation. Missing or expired results do not establish non-payment or authorize a new purchase.
- Preserves durable guided Task checkpoints: fresh or `REGISTER_PENDING` calls require caller-owned durable storage before Register; a valid saved `REGISTERED` checkpoint resumes without repeating Register or requiring another save of that phase.
- Synchronizes the package, SDK fallback, transport user agents, and MCP Observation build identity to `1.18.2`. The accepted package definition explicitly includes `eth-hash[pycryptodome]>=0.3.1`; other dependency and support declarations are retained.

The historical `v1.18.0` canonical Task fixture, its `target_release` value, and the contractual `/1.0` user agents retain their original identities. They are contract identifiers and do not report the current package version.

## Verification boundary

The accepted implementation and targeted correction evidence is retained. The native Windows check covers one isolated journal create/replace/load and same-process descriptor guard-contention condition. It does not establish complete Windows, macOS, network, or filesystem qualification, and the documented platform support boundaries are unchanged.

Public source promotion, GitHub Release, PyPI, MCP Registry, and Hondō deployment identities are recorded separately.
