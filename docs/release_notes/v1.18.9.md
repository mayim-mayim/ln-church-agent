# SDK 1.18.9 candidate

URL Choice & Reason adds typed discovery, Claim, answers, public/private results,
Requester registration and read recovery. Claim/answer journals durably preserve
original bindings across process restarts. The private reason is excluded from
normal serialization and preserved exactly on the wire.

Immediate v2 is the default discovery/registration version, with a dedicated Claim
schema and the fixed Agent role User-Agent. Explicit v1 and saved v1/v2 Report,
credential and registration recovery retain their original version.

Both normative packs are mirrored byte-for-byte from Hondo c1 `4e14024b7a0b7c3fbd54a2ad01e69ddab7be7efb`.
The SDK connects their descriptor/digest/profile values to runtime validation and
role dispatch. Isolated integration uses actual Hondo registration/execution/read
adapters with synthetic persistence/provider/chain inputs. It makes no production,
real-payment, external target or live Jev qualification claim. The backend's known
F01 deadline-crossing correction remains owned by Development Control; the SDK
introduces no workaround, alternate Claim or purchase.

The deterministic-runtime Summary, version metadata, platform qualification
boundaries, memory-only Access Quota recovery and real terms-check POST explanation
are aligned. Dependencies, build method and declared Python floor are unchanged.

The published 1.18.8 documentation corrections are retained from public commit
`13411e7147cd920152ac381b6c0b2b9499046a6a`. Its live-payment evidence does not qualify
new 1.18.9 artifacts. Candidate artifact filenames, sizes, SHA-256 and Linux/Python
3.11 source/fresh-wheel results are returned separately to Development Control.
Candidate creation is not acceptance, freeze, deployment or public release.
