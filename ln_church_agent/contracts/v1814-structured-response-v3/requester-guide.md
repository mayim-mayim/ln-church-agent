# APS requester contract

Use preparation -> authenticated preparation read -> preview confirmation -> quote -> existing x402 task-offer registration. Quote state is QUOTED, not preparation READY. The quote freezes selections, plan, profile groups and server pricing. Obtain a new preparation for changed inputs. Preparation/quote never charge. Preserve the registration reference, quote, authorization and original request for read-only recovery; never automatically start a second purchase. APS_ORDER_V1 and STRUCTURED_RESPONSE_V3 references are the existing profile-bound UUID, not a raw authorization hash. See requester-contract.json for the closed request/response schemas and fixed CSV example for custom v3 imports.

APS uses b+(k+g)s; generic custom v3 uses s only. INCLUDE groups use their direct source Task key; other research Tasks use their own reservation key. Groups never merge across orders. Profile targeting uses the complete accepted current-order research union, including rejected/compensated answers and excluding Claim-only addresses. Four profile items are required; model is optional and self-reported.

POST /api/agent/aps/read-challenges accepts schema_version, resource_kind (order/study/profile_task), resource_id and payer. Its four-field response contains schema_version, typed_data, challenge_token and expires_at. Verify the exact APSRead domain/types/message, payer, resource, audience and typed expiry. POST /api/agent/aps/read requires the complete schema_version/challenge_token/typed_data/signature/view envelope plus the view-specific query. Address alone grants nothing. Use view=order, study, answers, answer, profile or profile_analysis, not study_results/profile_results.

An order proof grants only the signed order; no query.order_id substitution. A study proof requires query.order_id identifying an owned order in that study. A profile_task proof grants only that purchased Task's profile view. Purchaser study/answers/answer work before public closure and contain only this order's published research plus its explicitly frozen public source. They do not publish the study or grant another order's private bodies. Public GET remains closed until a research Task closes; profiles are never included as research bodies. Old snapshots retain current moderation guards.

study returns an immutable purchaser snapshot with canonical context, typed source_tasks, aggregate and profile reservation summaries. answers defaults to the all-Agent address union, with answers[] references and measurement for the same address/context/wave. view=additional_answers lists deep/common bodies; kind=deep_dive|common_comparison filters it. view=wave_comparisons lists paired differences. answer requires submission_id and returns snapshot_id, row and original Task metadata. Read report items from row.report.items, numeric quality from row.quality and content/Jev details from row.content/evaluation_details. Do not apply current-wave questions to old answers.

Study/profile pages default to10 and allow10/25/50/100. Cursors bind snapshot, order/payer scope, view/filter, sort, page and size. Follow cursor without changing those values; renewed proof for the same payer/order can continue the same old snapshot. A missing old snapshot returns410 rather than switching to latest. Empty page1 has zero rows/pages and null cursors. The older Task results route and order's embedded Task rows remain maximum10; use the study/profile read APIs for complete traversal.

profile requires task_id with an order/study proof, or uses the signed profile_task ID. It returns immutable private rows, summary and original Task metadata. Order reservations with kind=PROFILE identify purchased profile entry points. profile_analysis uses current-order groups only and page/page_size (maximum10); it is a current analysis rather than a research snapshot. Keep research/profile received_at values, required non-disclosures, optional model missing/low quality and self_reported indicators. Do not fill absent attributes with another order's historical profile.

aggregate.axes is an object keyed "1" through "5", not an array. Preserve numeric item counts and decimal-string fraction numerators/denominators; null is missing/insufficient, not zero. Use server values for display and do not recompute canonical scores from rounded values. A D alone contains18 APS items plus2 category/comparison items; it is not a completed20-item APS score. Same-person B+D is joined only under the original canonical context/wave. Different people must not form a personal total.

Known target aliases use existing private_reference_items with item_id=a1_2. Supply exact aliases separated by newline, comma, semicolon or Japanese comma. They remain private. NFKC/casefold scanning of all B payload strings precedes quote, independently of the semantic safe result; unsafe B retains its selection for correction and cannot create a payment intent.

For an unpublished private source history, source_read_proof is a complete signed study read envelope with view=study and query.order_id equal to the original owned order. Public source history requires no proof. B has a stable per-Task opaque wire context_id and can withhold INCLUDE/EXCLUDE sources during intake. Preserve original submission context/bytes/hash through replay. A legitimate later B keeps prior public D history readable. Deleted needed references are not reconstructed and fail before purchase; newly supplied conditions require a new version.

B4 updates this candidate's requester reports/prior contract/guide and manifest identity; responder wire, evaluation, question bank and fixed CSV are unchanged from B2. This unpublished pack must be handed off by exact manifest digest; do not mirror B2/B3 under the B4 digest. Real provider/signature/money operations remain under separate Release authority.

Study reports are frozen with the study snapshot, canonical context and wave. reports.state=AVAILABLE includes categories/competitors rows (raw name/URL, normalized key, votes), outside_limit_count, tied_at_cutoff and unknown.category/competitors. Categories are limited to3, competitors to5. Only eligible DISCLOSED/REEVALUATION reports in that context/wave vote, with per-report quality>0.30 and one vote per address/candidate. Current-wave deep/common/profile and other waves do not contribute. AVAILABLE with empty rows and zero unknown is a normal empty result; unknown counts remain distinct. UNAVAILABLE has null groups/unknown; do not turn it into zero or reconstruct an old snapshot from current pages.

Every answer detail includes prior. Non-deep prior is null. Deep prior has snapshot_id and separate whole/personal structures: whole.state=AVAILABLE contains the original frozen source Task and APS aggregate (without an individuals list); personal.state=AVAILABLE contains only this respondent's original source row, joined to whole.task by Task/context/terms. Missing personal history is NONE, inaccessible/invalid history UNAVAILABLE, both with row=null. Missing personal body can leave whole AVAILABLE; missing/invalid source makes both UNAVAILABLE with null values and snapshot_id=null. Always render original source questions/conditions from whole.task and the original personal report, separately from the current deep Task and current study. No current value, another person, another order's private source/profile, Claim token or private storage key can substitute for a missing prior. Latest source deletion/publication-stop guards remain in force.
